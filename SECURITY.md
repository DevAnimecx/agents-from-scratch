# Security policy

Do not paste API keys, personal data, or production prompts into issues, pull requests, notebooks, or chat logs. The examples are educational and offline-first; they are not a security boundary.

For a suspected vulnerability in the code or release artifacts, open a private security advisory on GitHub for this repository rather than publishing exploit details. Include the affected path, Python version, reproduction, and impact. Maintainers will acknowledge reports and coordinate a fix before public disclosure when appropriate.

Before deploying a lesson artifact, add authentication, authorization, network egress policy, input/output limits, secret management, PII handling, tracing redaction, and dependency pinning.
